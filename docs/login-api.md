# 登录接口约定

当前登录使用 `MockLoginRepository`，不调用网络接口，也不需要启动后端。演示账号为 `admin / 123456`，验证通过后等待两秒返回 `userName = "admin"`、`userRole = "材料员"`；账号密码错误时返回失败，页面显示“账号或密码错误”。模拟仓库不保存 Token，退出仍走现有页面状态清理与导航流程。

以下协议由用户授权先定义，保留供后续后端实现参考。后续章节中的网络配置、Token 保存与失效回调属于预留接入设计，当前未启用；本次保留用户对真实网络实现的删除，不恢复这些文件。

## 地址与请求

- 方法：`POST`
- 路径：`/login`
- 请求类型：`Content-Type: application/json`
- 电脑上的服务地址：`http://localhost:8080/login`
- Android Studio 官方模拟器访问该服务：`http://10.0.2.2:8080/login`
- 真机通过局域网访问时，将 `10.0.2.2` 改为电脑实际的局域网 IP，后端需监听可访问的网络接口。

基础地址统一配置在 `core/network/HttpClient.kt` 的 `BASE_URL`，末尾保留 `/`。当前地址用于本地开发。服务器配置页暂未持久化配置，其输入不会修改此地址。

客户端只显式设置 `callTimeout` 为 100 秒，限制整次网络调用的累计时长，包括重试与重定向。连接、单次读取和单次写入使用 OkHttp 默认的 10 秒超时，因此某个阶段可能在总上限之前超时。100 秒沿用当前示例，并非所有登录接口的固定标准；后端有明确耗时要求时再调整。超时沿用请求失败提示，不清除 Token。

请求 JSON 示例：

```json
{
  "username": "demo",
  "password": "example-password"
}
```

`username` 和 `password` 均为必填字符串。客户端会去除账号两侧空白，密码保持输入原样；空账号或空密码在页面直接拦截。示例账号不代表后端必须接受的真实账号，认证由后端完成。

## 成功响应

HTTP 状态码：`200`。响应类型：`Content-Type: application/json`。

响应直接返回人员信息，不使用 `code`、`message`、`data` 包装：

```json
{
  "userName": "示例用户",
  "userRole": "材料员",
  "token": "example-access-token"
}
```

`userName`、`userRole` 和 `token` 均为必填字符串，分别表示人员名称、角色和访问凭证。Token 必须非空白。缺少必填字段或响应无法解析时，客户端展示请求失败，保持在登录页。

客户端将 Token 保存在 `HttpClient` 单例内存中，进程重启后清空。Token 的内部格式由后端决定，客户端按不透明字符串使用，不解析 JWT、不自动刷新、不持久化，也不将凭证或人员信息传入导航路由。

## 业务请求与凭证失效

登录请求不附带已有 Token。对同一基础地址的协议、主机和端口发出的其他请求，客户端在有 Token 时统一添加：

```http
Authorization: Bearer example-access-token
```

只有附带 Token 的请求返回 HTTP `401` 时，客户端才在清理前比对本次请求携带的 Token 与当前值，相同时清空 Token 并调用 `onTokenExpired`。其他主机、端口或协议的请求不附带该 Token。

当前为基础教学版本，Token 和回调均使用普通变量，不使用同步注解、锁或会话版本号。多请求同时处理登录态时，不保证失效通知去重或新旧凭证隔离；接入此类场景前需要补充会话保护。如果后端重新签发完全相同的 Token，客户端不会把它识别成不同会话。

`onTokenExpired` 在 OkHttp 请求线程执行。`AppNavHost` 注册回调后切换到主线程，清理旧页面返回栈并进入登录页；离开组合时解除回调。若通知处理前已经重新登录，不再执行此次跳转。`/login` 返回 HTTP `401` 只表示账号或密码错误，不触发全局过期回调。

用户主动退出时，通过 Repository 调用 `HttpClient.clearToken()`，再清理首页状态并导航到登录页。当前没有后端退出或撤销凭证接口，本地清除不撤销后端已签发的凭证，也不取消已发出的请求。

## 失败响应

| 情况 | HTTP 状态码 | 客户端行为 |
| --- | --- | --- |
| 账号或密码错误 | `401` | 显示“账号或密码错误”，停留在登录页 |
| 请求格式错误 | `400` | 显示“登录失败，请检查网络或稍后重试” |
| 服务端异常 | `500` 或其他非成功状态码 | 显示“登录失败，请检查网络或稍后重试” |
| 断网、超时、解析错误、成功响应体为空 | 无有效登录结果 | 结束加载，显示同一请求失败提示 |

失败响应体可以为空，客户端不解析其内容；账号错误必须使用 HTTP `401`，不能以 HTTP `200` 返回错误消息。加载期间重复点击不会发起重复请求。

## 运行前提与边界

- 后端需要先启动并监听 `8080` 端口。
- Android 客户端已具备网络权限和 HTTP 访问配置。
- 首页当前使用独立模拟人员信息，因此登录响应中的姓名不会自动替换首页姓名。
- 当前 Hilt 绑定使用 `MockLoginRepository`；未来接回真实接口时再切换为真实实现。
