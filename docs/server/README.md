# 服务端数据库与演示数据交接

所有演示业务数据只存放在 MySQL 8 中，PDA 只通过真实接口查询和提交。PDA 不内置账号、单据、库存、借还记录或告警，也不在网络失败后生成本地成功结果。Room 缓存仍只保存此前真实查询的返回值。

## 文件

- `schema.sql`：从上级《数据库设计说明》的 SQL 代码块导出的 31 张 MySQL 业务表及外键；不包含 Android SQLite 缓存表。
- `seed-demo.sql`：数据库演示数据，只用于独立开发数据库。数据在一笔事务内插入，重复执行会因唯一键失败，不覆盖已有业务记录。
- 上级《PDA服务端接口契约.md》是 API 实现依据；不得为演示增加 PDA 专用的假接口或固定返回值。

本次未连接实际 MySQL，未执行这些脚本。服务端 agent 需要建库执行、检查查询投影和事务结果，完成后记录验证信息。

## 执行准备

1. 创建一个空的 MySQL 8 开发数据库，使用 utf8mb4；明确选中该库后执行 `schema.sql`。不对生产数据库执行演示数据脚本。
2. 用服务端实际登录模块的密码哈希算法生成测试账号的密码哈希。在同一个 MySQL 会话设置 `@pda_seed_password_hash`，再执行 `seed-demo.sql`。脚本不提供明文密码或默认密码；未设置变量时，users.password_hash 的非空约束使导入失败。
3. 执行时遇到错误必须停止并回滚，不使用继续忽略错误的模式。脚本不会删除旧数据、禁用外键或覆盖真实账号。
4. 服务端逐字段实现 API，确认使用数据库查询。登录账号为 `pda_demo`，工号为 `DEMO0001`，密码由第 2 步的执行者自行提供。

示例会话结构如下，其中密码哈希必须替换为服务端生成的真实有效哈希：

```sql
SET @pda_seed_password_hash = '<服务端生成的密码哈希>';
SOURCE schema.sql;
SOURCE seed-demo.sql;
```

## 场景与数据

| PDA 模块 | 数据库入口 | 初始场景 |
| --- | --- | --- |
| 普通上架 | DEMO_PA01 / DEMO_IN01 | 3 件，1 件已上架，2 件待上架 |
| 工单拣选 | DEMO_PK01 / DEMO_BO01 | 2 件，1 件已拣选，1 件待拣选 |
| 工单归还上架 | DEMO_PA02 / DEMO_RT01 | 归还后待上架的单件 |
| 临时借出 | DEMO_TB01 | 已建单、待完成 TEMPORARY 其他拣选 |
| 临时归还 | DEMO_TR01 / DEMO_TB02 | 单件已借出，逐件填写实际货位后直接在库 |
| 其他拣选 | DEMO_OP_* | 临时、送检、送修、报废、退货来源 |
| 其他上架 | DEMO_OA_* | 仅送检返回、送修返回，不存在报废或退货归还上架 |
| 库存 | DEMO_WH | 不同库存状态、好坏件及不可复用的历史终态 RFID |
| 超期告警 | DEMO_ALERT08 | 关联仍在借的 DEMO_LOAN08 |

RFID 是 24 位十六进制编码，前缀为 D17A。它们是数据库开发记录，不代表真实标签。实机联调时必须由服务端按正常入库、绑定流程准备真实 EPC，不能在 PDA 中把演示编码替换成假读签结果。

送检、送修、报废和退货来源的完整业务表不在本次 PDA 表单范围内，脚本将这些任务的 `source_ready` 设为 FALSE。服务端 agent 必须在自己实现的来源业务中准备对应单据及合法审批/返回结果，校验通过后再维护 ready 状态。不得为了演示直接绕过来源存在性、好坏件、仓库或审批校验。临时来源已有 temp_borrow_orders，可直接按接口契约校验。

日期以执行时的 UTC 时间生成；超期借出为 7 天前，应还日为 2 天前。演示数据只表述确定的状态，不由 PDA 推测借用周期。

## 前端现有设备测试

旧设备测试中的账号、姓名、服务器地址、单号、RFID 和货位已改为运行参数，不提供本地默认演示值。读取入口为 TestDemo.kt 的 `testData(key)`；它不请求或创建业务数据，缺少参数会明确失败。

参数包括 `profileText`、`username`、`password`、`invalidUsername`、`invalidPassword`、`serverHost`、`putawayOrderNo`、`inboundOrderNo`、`rfid1`、`rfid2`、`completedRfid`、`location1`、`location2`、`toolDialogText`、`foreignLocation`、`materialCode`、`batchNo`、`warehouseName`、`toolName`、`operatorName`。这些值由测试环境中的真实数据库记录和有效服务器配置提供。不要把密码或环境值提交回 Android 代码。

本次未进入设备测试阶段，也没有新增测试类。旧用例的状态准备、固定数量断言和连接耗时假设仍需在测试阶段对照真实后端调整；不能据此声称既有测试已经通过。每个写入用例需要隔离的服务端数据，不能并发修改同一演示单据。
