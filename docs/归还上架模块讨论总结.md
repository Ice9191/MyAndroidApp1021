# 归还上架模块讨论总结

本文记录归还上架模块的文档要求、当前代码差异和讨论中的页面方案。页面方案尚未实施；标记为“建议”或“待确认”的内容，不代表客户已确认的需求。

参考：[《工器具库系统文档v2.docx》](D:/Cache/xwechat_files/wxid_8hqhdb6yab4x22_974e/msg/file/2026-11/工器具库系统文档v2.docx)的“仓库”“工单归还”“归还上架”“库存明细”“工具送修”正文及相关配图。

## 1. 文档规定的业务流程

1. 作业人员归还工具，一体机完成归还核验，库存由“已借出”变为“待上架”。
2. 系统自动生成上架单，根据货位占用情况和器具类别推荐上架货位。
3. PDA 按工具明细逐条扫码，核对工具并确认实际货位，允许现场调整货位。
4. 每条上架成功后，该明细由“待上架”变为“已上架”，对应库存由“待上架”变为“在库”，回写实际货位。
5. 部分明细完成时，上架单为“部分上架”；全部明细完成后为“已上架”。
6. 记录上架人、上架时间和实际货位，关联原归还业务。

PDA 本模块处理的是归还后的上架任务，操作主单为“上架单”。上架单号、关联归还单号、工单号应分别表达。

## 2. 页面合并方案

### 2.1 页面结构

采用本次讨论提出的结构：

1. 上架单列表：选择单据，点击“开始上架”。
2. Scan 页面：查看工具明细、完成 RFID 核对，点击某一条工具明细。
3. 底部抽屉：展示当前工具、推荐位置及实际货位，点击“确认上架”，只提交当前这一条。
4. 上架成功后更新明细和单据进度，留在 Scan 页面继续处理下一条。

原 `ReturnConfirmScreen` 的确认内容合并到 Scan 页的单条上架抽屉。按此方案实施时，可取消原“下一步”及独立确认页跳转。

归还上架本次讨论的方向是逐件确认；抽屉内容按用户提供的单件工具示意图组织。

### 2.2 列表及单据信息

| 位置 | 调整方向 |
| --- | --- |
| 搜索框 | 以上架单号搜索为主，现有“请输入归还单号”应调整；是否同时支持关联归还单号搜索待确认 |
| 单据标识 | 展示上架单号，关联归还单号及工单号分别展示 |
| 进度 | 使用“上架进度”，统计已上架数量和总数量 |
| 单据状态 | 待上架、部分上架、已上架 |
| 人员与时间 | 区分原归还人、归还时间和本次上架人、上架时间 |

文档没有要求在 PDA 上架时重新填写归还人工号，现有必填项缺少依据。建议归还人从关联单据展示，上架人由当前登录账号带出；具体人员来源及代上架规则待确认。

### 2.3 工具卡片选中效果

- 交互加在 `ToolsScanList` 的 Tab 内容区内，即每一张工具明细卡片上。
- 按触屏操作理解用户所说的 hover：点击卡片后选中，并打开对应抽屉。
- 沿用 `ReturnManualContent` 所使用的 `ManualScanCard` 视觉效果：蓝色边框、轻微上浮和阴影。现有效果为选中边框 `2.dp`、上浮 `2.dp`。
- 每次选中一条明细，与人工读取页的多选操作区分。
- 点击卡片只负责选择和打开抽屉，不自动标记为“已读取”或“已上架”。

关于可操作范围的建议：未读取工具可以查看信息，确认前应完成 RFID 核对；已上架工具可以查看结果，但不能重复确认。具体入口限制属于交互建议，文档没有规定对应的 Tab 或按钮布局。

## 3. 单条上架确认抽屉

### 3.1 抽屉内容

| 内容 | 展示或操作方式 | 依据或状态 |
| --- | --- | --- |
| 标题 | 上架确认 | 页面方案 |
| 工具信息 | 当前工具编码、名称、RFID | 用户示意图及工具核对需要 |
| 推荐位置 | 展示系统推荐仓库、推荐货位 | 文档要求系统推荐货位 |
| 仓库 | 系统带出，锁定显示 | 文档规定锁定各业务页面的仓库控件；具体带出来源待确认 |
| 实际货位 | 默认带出推荐货位，支持现场调整 | 文档允许实际货位与推荐货位不同 |
| 货位操作 | 支持选择货位，并接入 PDA 货位码扫描；候选货位应属于当前仓库 | 用户示意图与文档扫码绑定要求 |
| 底部按钮 | 取消、确认上架 | 页面方案；确认只作用于当前明细 |
| 关闭入口 | 右上角关闭、下滑关闭或返回 | 交互建议 |

用户示意图中的“仓库可任意下拉切换”与现有文档的仓库锁定规定不同。按现有文档实施时，应锁定仓库；是否允许跨仓上架需另行确认。

工具与实际货位必须逐条对应。例如三件工具分别上架到 A1-1、A1-2、A1-3，应分别记录，不能使用一个公共货位覆盖全部 RFID。

### 3.2 按钮及关闭行为建议

| 操作 | 结果 |
| --- | --- |
| 打开抽屉 | 展示当前工具和货位信息，不提交业务数据 |
| 修改实际货位 | 仅修改当前明细的待提交值 |
| 确认上架 | 核对当前明细、RFID 和实际货位后提交；提交期间显示“提交中”，防止重复提交 |
| 提交成功 | 更新当前明细和单据进度，关闭抽屉，留在 Scan 页继续上架 |
| 提交失败 | 保留抽屉和输入内容，展示失败原因，允许重试 |
| 取消、关闭、下滑或返回 | 不提交；建议丢弃本次未保存的货位调整，保留已读取结果 |

单条抽屉已经承担确认作用，建议不再增加一层相同内容的确认弹窗。

## 4. 读取状态、上架状态和库存状态

以下状态应分别表达：

| 状态维度 | 含义 |
| --- | --- |
| 已读取／未读取 | 本次 RFID 核对情况，不能代表业务已完成 |
| 待上架／已上架 | 单条上架明细的业务状态 |
| 待上架／部分上架／已上架 | 根据明细完成情况汇总的上架单状态 |
| 库存状态 | 普通上架成功后，由待上架变为在库 |
| 好坏件状态 | 工具质量状态，与库存状态分别记录 |

逐条上架后，应及时保存结果，允许其他未完成明细后续继续处理，不要求整单全部读取后才能提交第一条。

“在库”和“坏件”在系统其他场景可以同时存在，因此不能把“坏件”当作库存状态，也不能把“在库”直接等同于“好件”。

## 5. 坏件与待送检工具

### 5.1 现有文档明确规定的处理

- 工单归还阶段发现损坏，可以登记为“坏件”，后续进行工具送修。
- 归还上架阶段，对于归还时已经标记损坏、待送检的器具，不再推荐上架货位，引导转入送修或送检流程。
- 工具送修功能清单安排在一体机端创建业务单据，PDA 不直接把异常工具标记为“已送修”。

按上述要求讨论过的页面建议：坏件卡片显示标识；点击后展示工具信息、已有故障描述和处理提示，关闭正常上架确认入口，引导材料员办理后续处理。具体异常抽屉样式属于建议，文档没有给出该页面。

其他正常工具应继续上架，异常工具保留在单据中。异常工具不得由前端直接删除、计作已上架或随意从总数量中扣除。

### 5.2 用户提出的“坏件允许上架”方案：待确认

用户提供的提示文字表达了另一种处理方向：坏件也可以放回实际货位，保留坏件标记、禁止借用，后续送修。

讨论后建议的文案为：

> 该器具归还时已标记为坏件。确认上架后，将记录实际货位并保留坏件标记，暂不可借用，待后续送修处理。

该文案仅适用于客户确认“坏件允许上架”的规则后。它与现有文档“不推荐上架货位、引导送修”的规定存在差异，不能作为已经确认的需求直接实施。

如客户决定采用该方案，需要同步明确坏件可放置的货位、上架后的库存状态、禁止借用规则及后续送修衔接，并修改原业务文档。

### 5.3 本次不纳入的额外建议

“系统显示好件，但上架时发现实物损坏，在 PDA 抽屉中新增‘发现损坏’入口并登记坏件”是助手提出的额外建议。

现有文档没有明确要求这项 PDA 功能。本次不将该入口、故障描述填写及上架阶段补登记坏件作为既定需求。

### 5.4 文档尚未说明的异常衔接

归还上架正文要求对坏件引导送修，但工具送修的库存状态图从“在库”流转到“已送修”。归还后仍处于“待上架”的坏件如何进入送修，文档没有明确说明。

若一张上架单有 5 件工具，其中 4 件正常上架、1 件坏件待处理，可以分别展示完成数量和异常数量；异常处理后原单如何结清，需要后端业务规则明确，前端不能自行把整单改为“已上架”。

## 6. 当前代码需要更正或补齐的地方

以下为本次整理时核对到的现状，尚未修改代码。

| 当前实现 | 更正方向 |
| --- | --- |
| 列表、Scan 页仍以“归还单号”展示，列表显示“归还进度” | 明确上架单主体，区分关联归还单号，调整为上架进度 |
| 确认页将当前单号显示为“原借出单”，状态固定显示“待上架” | 使用正确单据字段，状态由实际数据决定 |
| 确认时必填归还人工号 | 按上架业务区分归还人与上架人，不沿用缺少文档依据的必填限制 |
| 全部工具共用一个货位，提交一个货位加多个 RFID | 按当前明细记录、校验和提交实际货位 |
| Scan 页仍需所有工具已读取才能点击下一步 | 按单条抽屉方案逐条完成，支持部分上架 |
| 明细只有本次读取标记和时间 | 补齐业务上的上架状态及对应结果，与读取状态区分 |
| 提交仅模拟等待后返回列表 | 实际成功后更新明细、数量、单据状态及实际货位；库存联动由后端完成 |
| 切换单据只替换单头并重置读取标记，仍使用同一组模拟明细 | 按所选上架单加载对应明细，模拟数据也应按单据关联 |
| RFID 扫描按钮尚未接入，“扫描库码”仅保存输入文字 | 后续接入真实读取、货位解析和校验 |
| 尚未表达工具质量及可正常上架资格 | 根据后端业务结果展示坏件或待送检提示，并按最终确认规则限制操作 |

当前状态标签已经是“待上架／部分上架／已上架”，这一点符合文档，无需再按旧的归还状态评价。

涉及文件主要为 `pages/returns/Model.kt`、列表与扫描页面及其 ViewModel、`ReturnConfirmScreen.kt`、`ReturnConfirmViewModel.kt`、`ReturnManualContent.kt`、`ToolsScanList.kt` 和相关导航。实施时保留 UDF/MVVM、共享 ViewModel 和无参数路由，通用组件通过状态及回调提供交互；按钮继续使用 `RoundedCornerShape(4.dp)`。
