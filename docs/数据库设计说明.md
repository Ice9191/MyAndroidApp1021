# PDA 数据库设计说明

版本：2026-11-17。本文说明 Android Room 查询缓存、DataStore 偏好与服务端 MySQL 8 业务数据。服务端由其他 agent 实现，本次不创建服务器程序或实际业务数据库。

设计依据为《工器具库系统文档v2》的正文、内嵌关系图及用户本次确认的业务规则。英文表列名称是本次授权制定的实现方案，不声称是已有生产数据库的物理名称。接口字段见 [PDA 服务端接口契约](PDA服务端接口契约.md)。

## 三种存储的职责

| 存储 | 内容 | 权威性 |
| --- | --- | --- |
| MySQL 8 | 人员权限、仓库货位、单件库存、任务单据、借还记录、告警、审计 | 业务唯一权威源；所有提交在事务内落库 |
| Android Room | 查询返回的完整 JSON 快照及缓存时间 | 只读缓存；不能从缓存推定提交成功 |
| Preferences DataStore | 服务器地址、端口、最近账号、加密登录会话 | 设备配置；密码不保存 |

## Android Room

入口 `local/AppDatabase.kt`；数据库文件 `tool_pda.db`；版本 1；启用 schema 导出，生成位置 `app/schemas/com.hxb.myandroidapp_1021.local.AppDatabase/1.json`。使用 Hilt 单例提供数据库和 DAO，不在主线程访问数据库，也不启用破坏性迁移。

唯一业务缓存表为 `query_cache`。缓存保存领域模型的序列化结果；各页的筛选条件、读签集合、弹窗、输入草稿和 ViewModel 不持久化为业务表。

| 列 | SQLite 类型 | 约束与含义 |
| --- | --- | --- |
| scope | TEXT | NOT NULL，复合主键之一；规范 API 基础地址 + `\|` + userId |
| resource | TEXT | NOT NULL，复合主键之一；资源路径，例如 `picking-orders` 或 `picking-orders/JC001` |
| payload | TEXT | NOT NULL，该资源的 JSON 快照；不含登录密码或 Token |
| savedAt | INTEGER | NOT NULL，保存时间的 Unix 毫秒值 |

```sql
CREATE TABLE query_cache (
    scope TEXT NOT NULL,
    resource TEXT NOT NULL,
    payload TEXT NOT NULL,
    savedAt INTEGER NOT NULL,
    PRIMARY KEY (scope, resource)
);
```

Room 自行维护内部 schema 标识，不手工创建其内部表。缓存按服务器和人员标识隔离；重新联网加载时覆盖同一资源。业务提交成功后使当前作用域缓存失效并通知页面重新加载。注销时清除本账号在当前服务器的缓存。修改数据库结构必须提高版本并提供迁移，不能静默销毁用户状态。

## DataStore 和凭证

文件为应用私有目录下的 `datastore/user_preferences.preferences_pb`；单例由 `UserPreferences` 管理。

| key | 类型 | 内容 |
| --- | --- | --- |
| server_host | String | 主机或带 http(s) 协议的主机地址，不携带业务路径、账号密码或查询参数 |
| server_port | String | 表单端口，保存前验证为 1 至 65535 |
| last_username | String | 最近成功登录的账号 |
| encrypted_session | String | LoginResponse 的加密结果，包含 Token、身份、权限和到期时间 |

会话使用 Android Keystore 的 AES-GCM 密钥加密，密钥别名 `tool_session`。存储格式为 Base64 编码的 `12 字节 IV + 密文及认证标签`。密钥不写入 DataStore；密码仅作为登录请求在内存中短时存在。设备重装或密钥失效后不可解密的会话按未登录处理。

服务器配置变化会清理会话，避免把旧服务端的凭证用于新地址。服务端 401 会使对应会话失效；网络故障不能替代有效的服务端登录或提交。用户不需要为服务器 IP 创建 MySQL 表。

## MySQL 公共约定

使用 InnoDB、utf8mb4。下方 DDL 用 `utf8mb4_0900_as_cs` 保持代码大小写明确；服务端在入库时规范化 RFID，账号、工号、仓库及货位编码不在每次查询中任意大小写变换。姓名、说明、备注允许中文。

数据库时间存 UTC，使用 `DATETIME(3)`；对外转换成 ISO 8601 UTC。纯日期使用 DATE。外部编码和单号使用 VARCHAR，不能把前导零丢掉。一个 RFID 对应一件实物，数量从单件明细和状态聚合，不能重复扣减。

所有历史业务记录和库存 RFID 保留，报废、退货、遗失采用状态及逻辑删除；不能通过删除行或覆盖原 RFID 实现重新入库。外键均不设置级联物理删除。用户、角色和组织使用启停状态，保留历史责任信息。

以下是支持当前 PDA 的完整业务表基线。上游和 PC 的完整表单、审批、设备和调度管理可在其服务端任务中扩展，不要求 PDA 增加相关接口。

## 基础档案与权限

```sql
CREATE TABLE warehouses (
    code VARCHAR(64) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    is_default BOOLEAN NOT NULL DEFAULT FALSE,
    default_marker TINYINT GENERATED ALWAYS AS
        (CASE WHEN is_default THEN 1 ELSE NULL END) STORED,
    UNIQUE KEY uk_default_warehouse (default_marker)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE locations (
    warehouse_code VARCHAR(64) NOT NULL,
    code VARCHAR(64) NOT NULL,
    name VARCHAR(100) NOT NULL,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    PRIMARY KEY (warehouse_code, code),
    FOREIGN KEY (warehouse_code) REFERENCES warehouses(code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE organizations (
    code VARCHAR(64) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    parent_code VARCHAR(64) NULL,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    FOREIGN KEY (parent_code) REFERENCES organizations(code),
    KEY ix_org_parent (parent_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE roles (
    code VARCHAR(64) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    data_scope ENUM('ALL','ORG_TREE','SELF') NOT NULL,
    enabled BOOLEAN NOT NULL DEFAULT TRUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE permissions (
    code VARCHAR(64) PRIMARY KEY,
    description VARCHAR(255) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE role_permissions (
    role_code VARCHAR(64) NOT NULL,
    permission_code VARCHAR(64) NOT NULL,
    PRIMARY KEY (role_code, permission_code),
    FOREIGN KEY (role_code) REFERENCES roles(code),
    FOREIGN KEY (permission_code) REFERENCES permissions(code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE users (
    id VARCHAR(64) PRIMARY KEY,
    username VARCHAR(64) NOT NULL,
    employee_no VARCHAR(64) NOT NULL,
    name VARCHAR(100) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role_code VARCHAR(64) NOT NULL,
    organization_code VARCHAR(64) NOT NULL,
    avatar_url VARCHAR(2048) NULL,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    created_at DATETIME(3) NOT NULL,
    updated_at DATETIME(3) NOT NULL,
    UNIQUE KEY uk_username (username),
    UNIQUE KEY uk_employee (employee_no),
    FOREIGN KEY (role_code) REFERENCES roles(code),
    FOREIGN KEY (organization_code) REFERENCES organizations(code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE auth_sessions (
    id VARCHAR(64) PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,
    token_hash BINARY(32) NOT NULL,
    created_at DATETIME(3) NOT NULL,
    expires_at DATETIME(3) NOT NULL,
    revoked_at DATETIME(3) NULL,
    UNIQUE KEY uk_token_hash (token_hash),
    KEY ix_session_user_expiry (user_id, expires_at),
    FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE materials (
    code VARCHAR(64) PRIMARY KEY,
    description VARCHAR(255) NOT NULL,
    specification VARCHAR(255) NULL,
    unit VARCHAR(32) NOT NULL,
    category VARCHAR(100) NULL,
    requires_inspection BOOLEAN NULL,
    inspection_cycle_months INT NULL,
    updated_at DATETIME(3) NOT NULL,
    CHECK (inspection_cycle_months IS NULL OR inspection_cycle_months > 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE inventory (
    rfid VARCHAR(128) PRIMARY KEY,
    material_code VARCHAR(64) NOT NULL,
    batch_no VARCHAR(64) NOT NULL,
    warehouse_code VARCHAR(64) NOT NULL,
    location_code VARCHAR(64) NULL,
    inventory_status VARCHAR(32) NOT NULL,
    tool_condition ENUM('好件','坏件') NOT NULL,
    fault_description VARCHAR(1000) NULL,
    first_inspection_date DATE NULL,
    next_inspection_date DATE NULL,
    deleted_at DATETIME(3) NULL,
    created_at DATETIME(3) NOT NULL,
    updated_at DATETIME(3) NOT NULL,
    FOREIGN KEY (material_code) REFERENCES materials(code),
    FOREIGN KEY (warehouse_code) REFERENCES warehouses(code),
    FOREIGN KEY (warehouse_code, location_code) REFERENCES locations(warehouse_code, code),
    KEY ix_inventory_available (warehouse_code, inventory_status, tool_condition, deleted_at, updated_at),
    KEY ix_inventory_material (material_code, warehouse_code, updated_at),
    KEY ix_inventory_inspection (warehouse_code, next_inspection_date),
    CHECK (inventory_status IN ('在库','待拣选','已备货','已借出','待上架','已送检','已送修','已报废','已退货','已遗失','盘亏'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;
```

默认仓库唯一索引最多允许一个默认库；服务端启动和登录还需检查恰有一个有效默认库。货位唯一性按仓库划分，同名货位不得跨仓误认。组织树必须由同步逻辑阻止循环引用。

`users` 一人一个角色，角色关联多个权限。组织、车间、班组显示文字不能作为越权判断依据。`auth_sessions` 不存原始 Token；密码哈希算法、初始化账号和密钥由服务端安全配置提供，不把演示密码写进仓库。

`inventory` 永久保存 RFID；逻辑删除后主键仍占用，重新入库必须生成新 RFID。`StockDetail` 通过联查 materials 得到描述、规格、单位、分类、是否送检和周期；周期对外显示如 `12个月`。`requiresInspection/inspectionCycle/nextInspectionDate` 的可空值用于明确未知资料，不把未知当成免检。

## 入库、工单与上架

```sql
CREATE TABLE inbound_orders (
    order_no VARCHAR(64) PRIMARY KEY,
    source_no VARCHAR(64) NOT NULL,
    warehouse_code VARCHAR(64) NOT NULL,
    status VARCHAR(32) NOT NULL,
    created_by VARCHAR(64) NULL,
    created_at DATETIME(3) NOT NULL,
    UNIQUE KEY uk_inbound_source (source_no),
    FOREIGN KEY (warehouse_code) REFERENCES warehouses(code),
    FOREIGN KEY (created_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE inbound_lines (
    order_no VARCHAR(64) NOT NULL,
    line_no INT NOT NULL,
    material_code VARCHAR(64) NOT NULL,
    batch_no VARCHAR(64) NOT NULL,
    quantity DECIMAL(18,3) NOT NULL,
    PRIMARY KEY (order_no, line_no),
    FOREIGN KEY (order_no) REFERENCES inbound_orders(order_no),
    FOREIGN KEY (material_code) REFERENCES materials(code),
    CHECK (line_no > 0 AND quantity > 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE work_orders (
    order_no VARCHAR(64) PRIMARY KEY,
    organization_code VARCHAR(64) NOT NULL,
    workshop VARCHAR(100) NOT NULL,
    team VARCHAR(100) NOT NULL,
    planned_at DATETIME(3) NOT NULL,
    FOREIGN KEY (organization_code) REFERENCES organizations(code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE borrow_orders (
    order_no VARCHAR(64) PRIMARY KEY,
    work_order_no VARCHAR(64) NOT NULL,
    borrower_id VARCHAR(64) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    created_at DATETIME(3) NOT NULL,
    UNIQUE KEY uk_borrow_work_order (work_order_no),
    FOREIGN KEY (work_order_no) REFERENCES work_orders(order_no),
    FOREIGN KEY (borrower_id) REFERENCES users(id),
    FOREIGN KEY (created_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE borrow_lines (
    order_no VARCHAR(64) NOT NULL,
    line_no INT NOT NULL,
    material_code VARCHAR(64) NOT NULL,
    quantity DECIMAL(18,3) NOT NULL,
    PRIMARY KEY (order_no, line_no),
    FOREIGN KEY (order_no) REFERENCES borrow_orders(order_no),
    FOREIGN KEY (material_code) REFERENCES materials(code),
    CHECK (line_no > 0 AND quantity > 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE picking_orders (
    order_no VARCHAR(64) PRIMARY KEY,
    borrow_order_no VARCHAR(64) NOT NULL,
    warehouse_code VARCHAR(64) NOT NULL,
    status ENUM('UNPICKED','PARTIALLY_PICKED','PICKED','CLOSED') NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    created_at DATETIME(3) NOT NULL,
    closed_at DATETIME(3) NULL,
    FOREIGN KEY (borrow_order_no) REFERENCES borrow_orders(order_no),
    FOREIGN KEY (warehouse_code) REFERENCES warehouses(code),
    FOREIGN KEY (created_by) REFERENCES users(id),
    KEY ix_picking_status (warehouse_code, status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE picking_lines (
    order_no VARCHAR(64) NOT NULL,
    line_no INT NOT NULL,
    borrow_order_no VARCHAR(64) NOT NULL,
    borrow_line_no INT NOT NULL,
    rfid VARCHAR(128) NOT NULL,

    recommended_location VARCHAR(64) NULL,
    picked_at DATETIME(3) NULL,
    picked_by VARCHAR(64) NULL,
    PRIMARY KEY (order_no, line_no),
    UNIQUE KEY uk_picking_rfid (order_no, rfid),
    FOREIGN KEY (order_no) REFERENCES picking_orders(order_no),
    FOREIGN KEY (borrow_order_no, borrow_line_no) REFERENCES borrow_lines(order_no, line_no),
    FOREIGN KEY (rfid) REFERENCES inventory(rfid),
    FOREIGN KEY (warehouse_code, recommended_location) REFERENCES locations(warehouse_code, code),
    FOREIGN KEY (picked_by) REFERENCES users(id),
    CHECK (line_no > 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE return_orders (
    order_no VARCHAR(64) PRIMARY KEY,
    borrow_order_no VARCHAR(64) NOT NULL,
    returner_id VARCHAR(64) NULL,
    returned_at DATETIME(3) NULL,
    created_by VARCHAR(64) NOT NULL,
    created_at DATETIME(3) NOT NULL,
    FOREIGN KEY (borrow_order_no) REFERENCES borrow_orders(order_no),
    FOREIGN KEY (returner_id) REFERENCES users(id),
    FOREIGN KEY (created_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE return_lines (
    order_no VARCHAR(64) NOT NULL,
    line_no INT NOT NULL,
    rfid VARCHAR(128) NOT NULL,
    loan_id VARCHAR(64) NOT NULL,
    returned_at DATETIME(3) NOT NULL,
    returner_id VARCHAR(64) NOT NULL,
    PRIMARY KEY (order_no, line_no),
    UNIQUE KEY uk_return_rfid (order_no, rfid),
    FOREIGN KEY (order_no) REFERENCES return_orders(order_no),
    FOREIGN KEY (rfid) REFERENCES inventory(rfid),
    FOREIGN KEY (returner_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE putaway_orders (
    order_no VARCHAR(64) PRIMARY KEY,
    origin_kind ENUM('INBOUND','WORKORDER_RETURN') NOT NULL,
    inbound_order_no VARCHAR(64) NULL,
    return_order_no VARCHAR(64) NULL,
    warehouse_code VARCHAR(64) NOT NULL,
    status VARCHAR(32) NOT NULL,
    created_by VARCHAR(64) NOT NULL,
    created_at DATETIME(3) NOT NULL,
    FOREIGN KEY (inbound_order_no) REFERENCES inbound_orders(order_no),
    FOREIGN KEY (return_order_no) REFERENCES return_orders(order_no),
    FOREIGN KEY (warehouse_code) REFERENCES warehouses(code),
    FOREIGN KEY (created_by) REFERENCES users(id),
    KEY ix_putaway_status (warehouse_code, origin_kind, status, created_at),
    CHECK ((origin_kind='INBOUND' AND inbound_order_no IS NOT NULL AND return_order_no IS NULL)
        OR (origin_kind='WORKORDER_RETURN' AND return_order_no IS NOT NULL AND inbound_order_no IS NULL))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE putaway_lines (
    order_no VARCHAR(64) NOT NULL,
    line_no INT NOT NULL,
    inbound_order_no VARCHAR(64) NULL,
    inbound_line_no INT NULL,
    return_order_no VARCHAR(64) NULL,
    return_line_no INT NULL,
    rfid VARCHAR(128) NOT NULL,
    warehouse_code VARCHAR(64) NOT NULL,
    recommended_location VARCHAR(64) NULL,
    actual_location VARCHAR(64) NULL,
    putaway_at DATETIME(3) NULL,
    putaway_by VARCHAR(64) NULL,
    PRIMARY KEY (order_no, line_no),
    UNIQUE KEY uk_putaway_rfid (order_no, rfid),
    FOREIGN KEY (order_no) REFERENCES putaway_orders(order_no),
    FOREIGN KEY (inbound_order_no, inbound_line_no) REFERENCES inbound_lines(order_no, line_no),
    FOREIGN KEY (return_order_no, return_line_no) REFERENCES return_lines(order_no, line_no),
    FOREIGN KEY (rfid) REFERENCES inventory(rfid),
    FOREIGN KEY (warehouse_code, recommended_location) REFERENCES locations(warehouse_code, code),
    FOREIGN KEY (warehouse_code, actual_location) REFERENCES locations(warehouse_code, code),
    FOREIGN KEY (putaway_by) REFERENCES users(id),
    CHECK (line_no > 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;
```

上游移位单与入库单以 `source_no` 去重；绑定后生成一件一行的库存和上架明细，原入库行保留多件数量。创建上架行时必须检查它的来源类型、来源单号与表头一致，且 RFID 已完成合法绑定。

工单借用单与工单一对一。拣选行保留原借用行关联，指定 RFID 并记录推荐货位；单据关闭后保留已拣结果，剩余行不再执行。`PickingOrder` 的车间、班组、计划时间、借用人联查 work_orders、borrow_orders、users；`totalCount/pickedCount/pendingCount` 根据完整行统计。

普通入库上架和工单归还上架共享物理上架表，分别由 `origin_kind` 隔离查询。`ReturnOrder` 的 wire 状态 `UNRETURNED/PARTIALLY_RETURNED/RETURNED` 对应表头中文状态“待上架/部分上架/已上架”；`orderNo` 映射 putaway_orders.order_no，`returnOrderNo` 映射其来源归还单。不要将 wire 字段 `returnedCount` 误建为“实际归还数量”列。

已上架状态由 `putaway_at` 判定；上架人、时间、实际货位保存在每行。表头 `operator/putawayTime` 为最近完成行的展示信息，不能覆盖每行历史。坏件和待送检异常行保持未完成，不从总数中删除；`canProcess/blockedReason` 为服务端依据质量、任务和库存状态计算的查询投影。

## 临时借还、占用和业务流水

```sql

    order_no VARCHAR(64) PRIMARY KEY,

    request_hash BINARY(32) NOT NULL,

    team VARCHAR(100) NOT NULL,
    remark VARCHAR(1000) NOT NULL,

    created_by VARCHAR(64) NOT NULL,
    created_at DATETIME(3) NOT NULL,
    UNIQUE KEY uk_temp_request (created_by, request_id),
    FOREIGN KEY (borrower_id) REFERENCES users(id),
    FOREIGN KEY (warehouse_code) REFERENCES warehouses(code),
    FOREIGN KEY (created_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_as_cs;

CREATE TABLE temp_borrow_lines (

    line_no INT NOT NULL,
    rfid VARCHAR(128) NOT NULL,
    borrowed_at DATETIME(3) NULL,
    borrowed_by VARCHAR(64) NULL,

CREATE TABLE loan_records (
    id VARCHAR(64) PRIMARY KEY,
    origin_kind ENUM('WORKORDER','TEMPORARY') NOT NULL,
    borrow_order_no VARCHAR(64) NOT NULL,
    borrow_line_no INT NOT NULL,
    work_order_no VARCHAR(64) NULL,
    rfid VARCHAR(128) NOT NULL,
    borrower_id VARCHAR(64) NOT NULL,
    operator_id VARCHAR(64) NOT NULL,
    borrowed_at DATETIME(3) NOT NULL,
    due_at DATETIME(3) NOT NULL,
    status ENUM('BORROWED','RETURNED','LOST') NOT NULL,
    returned_at DATETIME(3) NULL,
    returner_id VARCHAR(64) NULL,
    active_rfid VARCHAR(128) GENERATED ALWAYS AS
        (CASE WHEN status='BORROWED' THEN rfid ELSE NULL END) STORED,
    UNIQUE KEY uk_active_loan (active_rfid),
```

`work_order_no` 在临时业务允许为空，不要求一定存在上游工单；表单空字符串写库时转 NULL。临时人员输入必须解析工号，数据库保存人员 ID，响应再联查姓名，`returnerEmployeeNo` 联查工号用于再次打开表单。

创建临时借出单时，在一笔事务内锁住选中库存并创建占用、明细和其他拣选任务；`request_hash` 为规范化创建请求的摘要，用于识别同 requestId 的不同内容。状态由本单各行借出时间派生，`picked` 联查相关其他拣选行，不重复保存由前端维护的布尔值。

确认临时借出时检查所有行都已拣选，然后为本件创建 loan_records、借出事件、待还行。正常工单交接也可创建手工兜底待还行，支持文档要求的标签异常人工归还。loan_records 与 temp_return_orders 的多来源关联由 origin_kind 区分，服务层必须验证对应单据及行存在且匹配，不能只接受任意来源字符串。工单归还通过 return_lines.loan_id 关联原借用记录，不能根据同一 RFID 的任意历史借用进行核销。人工归还与一体机归还共同锁定同一 loan_records，防止两条通道重复核销。

同一 RFID 同时只能有一条在借记录，由 `uk_active_loan` 保证。库存分配只能有一个未释放占用，由 inventory_reservations 的主键保证。占用表的多来源关联也必须在服务层事务中校验；工单关闭释放未完成行占用，已备货件不得因此错误回到可借库存。

临时归还更新本行 actual_location、returner_id、returned_by、returned_at，并更新对应 loan_records 和归还事件；库存逐件直接恢复在库，同时关闭关联告警。表头 default_location 只作为再次输入的默认值，不能批量覆盖已归还件。不会创建其他上架任务。

other_tasks 的 `source_ready` 表示来源业务已完成执行前置条件，例如报废审批、送检/送修返回登记；它只能由相应服务端业务维护，不能由 PDA 提交。来源实体的完整业务表属于 PC/一体机服务端任务，服务层必须校验来源存在、状态和权限，不能把此字段当成任意开关跳过来源校验。

other_task_lines 的 `completed/canProcess/blockedReason` 对外字段分别由完成时间、来源状态、质量、库存和分配资格计算。完成数按所有行统计；未完成、部分完成和全部完成派生，closed_at 独立表达来源任务关闭。其他上架仅支持送检、送修返回；临时归还直接入库，报废/退货不支持归还上架，数据库 CHECK 同步限制。

告警通过 loan_id 联查工单、借用人、器具、借出时间、应还时间；超期天数由服务端使用业务时区和应还时间计算。借用周期、具体应还截止时刻和催还调度属于服务端既有参数/来源单据，不在 PDA 猜测；服务端创建借出记录时必须写入明确 due_at。PDA 不提供参数设置或告警处理接口。

操作日志与实际提交处于同一事务，按件记录状态和货位变化；同一批次的每个 RFID 都能追溯。日志保留新增者、操作时间及必要前后值，不保存密码、原始 Token 或认证请求 body；应用业务权限不允许篡改历史日志。

## 库存状态和事务清单

| 业务 | 前置条件 | 成功后 |
| --- | --- | --- |
| 普通入库上架 | 已合法绑定 RFID、待上架、有效目标货位 | 本件在库，保存实际货位 |
| 工单拣选 | 本单指定 RFID、在库或已分配待拣选、好件、占用匹配 | 已备货，记录拣选；不创建实际借出事件 |
| 工单交接（来源业务） | 已备货、交接校验通过 | 已借出，建立 loan_records 和借出事件 |
| 工单归还（来源业务） | 当前有效借出记录 | 核销借出，待上架，生成独立归还上架单 |
| 工单归还上架 | 待上架、好件且无待送检阻断 | 在库，逐件保存实际货位 |
| 临时其他拣选 | 本单占用的在库件 | 已备货 |
| 临时确认借出 | 本单全部拣选完成、本行未借出 | 已借出，创建待还行和借出流水 |
| 临时确认归还 | 对应当前在借记录、有效实际货位 | 本件直接在库、核销、归还流水、告警闭环 |
| 送检/送修拣选 | 来源满足执行条件、本单指定件 | 已送检 / 已送修，不可借用 |
| 送检/送修返回后上架 | 来源已登记合格返回、库存待上架 | 在库，保存实际货位 |
| 报废拣选出库 | 来源批准、在库且坏件 | 已报废，逻辑删除，保留 RFID |
| 退货拣选出库 | 来源批准、有效在库 | 已退货，逻辑删除，保留 RFID |
| 报废/退货后重新入库 | 新来源入库流程、新 RFID | 新库存记录；旧终态记录不变 |

确认事务采用 `SELECT ... FOR UPDATE` 锁住本次目标行和库存；一批 RFID 按规范编码固定顺序加锁以降低死锁概率。所有数量由行结果聚合，`总数 = 已完成 + 未完成`。分批提交只改变本批，重复确认返回现状。服务端不能先提交库存再异步补业务日志，也不能依靠前端计数替代数据库并发校验。

## 初始化和演进

先建立基础档案、有效默认仓库、货位、人员和角色，再创建来源业务单据。PDA 不预置管理员密码或固定业务数据。权限码、时间格式、空值和 wire 枚举必须与接口文档一致。

MySQL 表结构变更通过服务端版本化迁移管理；Room schema 单独版本化。不得把 SQLite 缓存表复制成服务端业务库，也不得将 DataStore 表单状态导入 MySQL。本文是可执行 DDL 基线和服务实现约束，实际服务器的建库、迁移执行、回滚演练和并发验证由服务端 agent 完成后记录结果。
